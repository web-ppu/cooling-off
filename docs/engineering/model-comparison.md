# AI 후보 모델 비교 — v0.2 (챗봇 등급 중심)

> 실서비스 운용 대상인 **챗봇 등급 후보 3종**(Claude Haiku 4.5 / GPT-4o-mini / Gemini 3.1 Flash-Lite)을 5축으로 비교한다.
> 라운드 1(사고 등급)에서 측정한 대화 품질 결과를 챗봇 등급에 합리적 추론으로 적용하고, 비용·API 연동은 챗봇 등급 공식 자료로 재계산했다.

---

## ⚠️ 본 비교의 한계 (팀에 공유 시 함께 보세요)

| 측정 방식 | 평가 축 |
|---|---|
| **직접 측정** (라운드 1, 사고 등급 모델 × Case A/B/C × 9 대화) | 사고 등급의 대화 품질·신호·요약 |
| **공식 자료 기반 산출** (벤더 가격표·SDK 문서) | 챗봇 등급의 비용·API 연동 난이도 |
| **합리적 추론** (사고 등급 결과 + 모델 등급 차이) | 챗봇 등급의 대화 품질·신호·요약 (예상) |

→ **챗봇 등급 직접 실측은 인프라 제약(PromptLayer 한도·결제 등)으로 미실시.** 운용 결정 전 짧은 실측 라운드 한 번 더 권장. 추정 결과는 [의사결정 가이드](#5-의사결정-가이드)에서 보수적으로 해석.

## 3. API 연동 난이도

| 항목 | Claude Haiku 4.5 | GPT-4o-mini | Gemini 3.1 Flash-Lite |
|---|---|---|---|
| 공식 SDK | `anthropic` (Py/JS) | `openai` (Py/JS) | `google-genai` (Py/JS) |
| 시스템 프롬프트 + 멀티턴 | ✅ 표준 | ✅ 표준 | ✅ 표준 |
| Prompt caching | ✅ 명시적 API | ✅ 자동 | ✅ 명시적 API |
| 한국어 응답 품질 | ✅ 강함 (Claude 라인 검증) | ✅ 강함 | ✅ 강함 |
| 인증 방식 | API 키 1개 | API 키 1개 | API 키 (AI Studio) **또는** GCP 서비스 계정 (Vertex AI) |
| 한국어 공식 문서 | ⚠️ 일부 번역 | ⚠️ 일부 번역 | ⚠️ 일부 번역 |
| 커뮤니티·예제 풍부도 | 중 | **상** (가장 풍부) | 중 |
| 응답 지연 | **~2~3초/500단어** | 빠름 | **가장 빠름** (Flash 대비 TTFT 2.5배) |
| 특이 이슈 | 토크나이저 변경 영향 | 사고 토큰 출력 비용 처리 | Vertex AI 경로는 GCP 학습곡선 |

### 종합 (비개발자 평가)

| 모델 | 평가 |
|---|---|
| Claude Haiku 4.5 | ✅ 단순. API 키 1개로 충분 |
| GPT-4o-mini | ✅ **가장 쉬움**. 자료·예제 가장 풍부 |
| Gemini 3.1 Flash-Lite | ⚠️ AI Studio 경로면 ✅ 단순, Vertex 경로면 ⚠️ |

→ 실제 통합은 개발자 검토 추가 권장.

## 4. 대화 품질 추정 (라운드 1 + 챗봇 등급 추론)

### 라운드 1 측정 결과 요약 (사고 등급)

| 모델 | 강점 | 약점 |
|---|---|---|
| Claude Opus 4.7 | 모순 추적·체감 비용 추적 가장 집요. Case C 흐름 가장 깔끔 | "약한 이유" 같은 도덕 평가 표현 (Case A) |
| GPT-5.5 Thinking | **중립성·구조 안정성 가장 강함**. 위반 횟수 최저 | 요약에 등록 정보 외삽 (Case A/B/C 모두) |
| Gemini 3.1 Pro | 빠른 통과·간결 요약. Case C 가장 깔끔 | 사용자 모호함을 단정으로 바꾸는 경향 |

### 챗봇 등급 추론 (벤더 라인 특성 유지 가정)

| 모델 | 예상 대화 품질 (사고 등급 대비) |
|---|---|
| **Claude Haiku 4.5** | Claude 라인의 한국어 톤·반말 강점 유지 가능. 다만 모순 추적·복잡 규칙 준수는 Opus 대비 떨어질 가능성 (모델 깊이 차이) |
| **GPT-4o-mini** | GPT 라인의 중립성·구조 안정성 일부 유지. 다만 5.5 Thinking 대비 응답 단순화 경향. 요약 외삽 패턴 가능성 잔존 |
| **Gemini 3.1 Flash-Lite** | Flash 라인의 빠른 통과·간결 요약 강점 유지. 빈도 외삽·단정 경향이 사고 등급보다 더 강해질 위험 |

### 공통 위험 (모든 챗봇 등급)

- **메타 태그 100% 실패** (라운드 1에서 사고 등급도 실패한 사항). 챗봇 등급에서도 유지될 가능성 매우 높음 → v1에서 **서버 사이드 후처리로 이관 필요**.
- 라운드 1의 3대 공통 실패 패턴(메타 태그·빈도 외삽·요약에 등록 정보 자동 삽입)이 챗봇 등급에서도 재현 가능성 큼.

## 5. 5축 통합 비교표

| 평가 축 | Claude Haiku 4.5 | GPT-4o-mini | Gemini 3.1 Flash-Lite |
|---|---|---|---|
| **대화 품질** (추정) | ⚠️ 톤 강함 / 모순 추적 약화 가능 | ✅ **중립성·안정성 강함** / 요약 외삽 약점 | ⚠️ 빠름 / 단정 경향 위험 |
| **신호 안정성** (메타 태그) | ❌ 추정 (사고 등급 0/3, 챗봇 등급 더 약할 위험) | ❌ 추정 | ❌ 추정 |
| **요약 품질** (추정) | ⚠️ 등록 정보 자동 삽입 위험 | ⚠️ 등록 정보 자동 삽입 위험 | ✅ Case C에선 가장 깔끔 (추정) |
| **비용** (100MAU/월, 캐싱 적용) | ~$2 | **~$0.3** | ~$0.5 |
| **API 연동 난이도** | ✅ 단순 | ✅ **가장 쉬움** | ⚠️ Vertex 경로면 복잡 |
| **장점** (1줄) | 한국어 톤·반말 자연스러움. Anthropic 안정 운영 | 가성비 최강. 통합 가장 쉬움. 중립성 안정 | 가장 저렴 + 가장 빠름. 간결 요약 강점 |
| **단점** (1줄) | 모순 추적·복잡 규칙 준수 약화 가능 | 5.5 대비 응답 단순화. 한국어 톤 강도 ↓ | 빈도 외삽·단정 경향 위험 |

> ⚠️ 신호 안정성 축은 세 모델 모두 ❌. **어떤 모델을 선택하든 [결정하기] 버튼 제어는 서버 사이드 후처리로 옮기는 게 v1의 전제다.**

## 6. 의사결정 가이드

### MVP 선정 (2026-05-12 확정)

→ **선정 모델: Gemini 3.1 Flash-Lite** ([model-selection.md](model-selection.md) 참고)
→ 결정 기준: **속도·운영비 최우선** + 한국어 톤은 충분히 좋음 수준.
→ 한국어 톤 이슈 발견 시 **Claude Haiku 4.5로 즉시 마이그레이션** (1~2시간 작업).

### 우선순위별 추천 (팀이 다른 우선순위를 둘 경우 참고)

| 우선순위 | 추천 모델 | 이유 |
|---|---|---|
| **속도·간결함·비용 최우선 (MVP 기본)** ✅ | **Gemini 3.1 Flash-Lite** | 최저가·최고속. Case C 같은 빠른 통과 시나리오에 강함. 100MAU 월 $0.5 |
| **한국어 톤·반말 자연스러움이 최우선** | Claude Haiku 4.5 | 라운드 1에서 Claude 라인이 한국어 톤·반말 가장 자연스러웠음 |
| **운영 안정성·통합 용이성** | GPT-4o-mini | 라운드 1에서 GPT 라인 중립성·구조 안정성 최강. 자료 가장 풍부 |

→ **본 비교는 추정 기반.** 운용 전 짧은 실측 라운드 권장. 단, 챗봇 등급 3종 모두 운용 비용이 매우 저렴하고 API 연동이 표준이라 실패 시 다른 모델로 마이그레이션 부담도 작음.

## 7. 한계 및 후속 권장

### 본 비교가 다루지 못한 것

- 챗봇 등급 직접 실측 (PromptLayer 한도 등 인프라 제약)
- 챗봇 등급 응답 시간 실측 (지연·체감 UX)
- 한국어 특수 표현(예: "어케 생각함?")의 챗봇 등급 모델별 이해도 차이
- 1000+ 동시 사용자 환경에서의 토큰 캐싱 효율 실측

### 후속 권장 (Week 3 이후)

1. **선택 모델 1개로 짧은 실측 라운드** — Case A·B·C 3개를 선택 모델로 직접 돌려 v1 프롬프트 검증
2. **메타 태그 서버 사이드 후처리 구현** — LLM에게 위임하지 말 것
3. **빈도 외삽 방지 강화** — v1 프롬프트에 사용자가 명시하지 않은 빈도 추정 금지 조항 강조 (이미 v1에 반영)
4. **요약 등록 정보 차단 강화** — v1 프롬프트에 등록 정보 재출력 금지 조항 명시 (이미 v1에 반영)
