# AI-프론트엔드 인터페이스 계약

> 개발자용. AI 응답 구조 + 프론트엔드가 phase별로 뭘 해야 하는지.
>
> **의사결정 배경**: [`../archive/adr-decide-flow.md`](../archive/adr-decide-flow.md)
> **시뮬레이션**: [`./ai-simulation-log.md`](./ai-simulation-log.md)

---

## 1. 왜 phase 필드가 필요한가

AI 대화에서 "결정 버튼을 언제 띄울지"를 프론트엔드가 판단해야 한다. 근데 AI 응답은 자연어 텍스트라서, "이 텍스트가 정보 수집 단계인지 관점 제시 단계인지" 프론트엔드가 자체 판단할 수 없다.

그래서 AI 응답에 **대화 단계를 알려주는 구조화된 신호(phase 필드)**를 같이 넣는다.

---

## 2. AI 응답 구조

```json
{
  "message": "35만원어치 귀찮음인 거야.",
  "phase": "gathering" | "perspective" | "closing",
  "summary": null | ["팩트1", "팩트2", ...]
}
```

| 필드 | 타입 | 설명 |
|------|------|------|
| `message` | string | 사용자에게 보여주는 AI 메시지 텍스트 |
| `phase` | enum | 현재 대화 단계. 프론트엔드 동작을 결정하는 핵심 필드 |
| `summary` | string[] \| null | `closing` 단계에서만 포함. 대화에서 나온 팩트 bullet 리스트. [결정할래] 누르면 이걸 팩트 요약 카드에 표시 |

---

## 3. phase 값별 프론트엔드 동작

| phase | AI가 하고 있는 것 | [결정할래] 버튼 | 채팅 입력창 | 예시 |
|-------|------------------|:---:|:---:|------|
| `gathering` | 정보 수집. 구체화 질문 | **숨김** | 활성 | "하루에 충전 몇 번 해?" |
| `perspective` | 수집한 정보를 가공해서 관점 제시 | **노출** | 활성 | "35만원어치 귀찮음인 거야" |
| `closing` | 대화 마무리 제안 | **노출** | 활성 (힌트: "아직 더 얘기하고 싶으면 말해") | "결정할 준비 됐어?" |

### 상태 전이

```
gathering → perspective: AI가 처음으로 관점 제시한 순간
perspective → closing: AI가 충분하다 판단하고 마무리 제안
perspective → gathering: (일반적이지 않지만) AI가 추가 정보 필요 판단 시
closing → perspective: 사용자가 "아직"이라고 하면 대화 계속
```

### [결정할래] 버튼은 한 번 나타나면 사라지지 않는다

`perspective`에서 버튼이 노출된 후, AI가 다시 `gathering`으로 돌아가더라도 버튼은 **유지**. 한 번이라도 관점이 제시됐으면 사용자가 언제든 결정할 수 있다.

---

## 4. [결정할래] 버튼 UI

- **위치**: 채팅 입력창 바로 위, sticky (스크롤해도 따라옴)
- **대화 영역과 겹치지 않음** — 입력창 영역이 버튼 높이만큼 올라감
- **버튼 노출 후에도 채팅 입력창은 그대로 유지** (대화 계속 가능)

---

## 5. [결정할래] → 팩트 요약 → [안 삼]/[삼] 플로우

```
[결정할래] 탭
  ↓
채팅 입력창 사라짐
  ↓
팩트 요약 카드 표시 (summary 필드 내용)
  ↓
[안 삼] / [삼] 대칭 버튼 표시
  ↓
탭 → 결정 상태 업데이트 (passed/purchased) + 결정 시각 기록
  ↓
5초 undo 토스트 (sonner)
  ↓
홈으로 이동
```

### 팩트 요약 카드

- AI의 마지막 `closing` 응답에 포함된 `summary` 필드를 bullet으로 표시
- **AI 판단/조언 없이 사실만** (원칙: 대칭, 판단 강요 금지)
- 별도 API 호출 없음 — 이미 `closing` 응답에 포함돼 있음

### summary가 없는 경우

사용자가 `perspective` 단계에서 `closing` 없이 바로 [결정할래]를 누른 경우 → summary가 null. 이때는 "요약 없이 결정" — 팩트 요약 카드 없이 바로 [안 삼]/[삼] 표시.

## 6. Hard Cap 10턴

### 정의

1턴 = 사용자 입력 1회 + AI 응답 1회. Hard cap 10턴 = 사용자 10회 입력 + AI 10회 응답.

### 10턴 도달 시 동작

- AI가 10턴째 응답에서 `phase: "closing"` + `summary` 포함 (맥락 인지 마무리)
- 채팅 입력창 비활성화
- [결정할래] 버튼 유지 (아직 안 눌렀으면 이때 노출)

### 10턴 도달 시 관점 제시 미완료 (edge case)

AI가 10턴 동안 `gathering`만 반복한 경우 (사용자가 극도로 짧은 답변만 함 등):
- AI가 수집된 정보 범위 내에서 **강제로 관점 제시 + 마무리** → `phase: "closing"` + `summary`
- 프론트엔드: 입력창 비활성화 + [결정할래] 버튼 노출

---

## 7. AI API 에러 처리

| 상황 | 프론트엔드 동작 |
|------|---------------|
| 응답 실패 (1~2회) | 토스트 "AI가 응답하지 못했어." + [다시 시도] 버튼 |
| 3회 연속 실패 | "AI 없이 결정할 수도 있어" + [결정할래] 버튼 강제 노출. 팩트 요약은 "요약 불가" 표시 |
| phase 필드 없음 / JSON 파싱 실패 | **Fallback: 3턴 이후 자동으로 [결정할래] 버튼 노출** (턴 수 기반 fallback) |

---

## 8. "결정할 준비 됐어?"에 "아직"

- AI가 대화 계속. 다음 관점 제시 후 다시 마무리 제안 가능.
- 2회 연속 "아직"이면 더 이상 제안하지 않고 대화만 계속. 사용자가 직접 [결정할래] 버튼을 누를 때까지.

---

## 9. API 비용 추산

시뮬레이션 기준 1회 대화 평균 5턴:
- System prompt (Layer 1): ~800 tokens (prompt caching 대상)
- 턴당 user+assistant: ~200 tokens
- 5턴 총: ~1,800 input + ~500 output ≈ 2,300 tokens
- Claude 3.5 Haiku 기준: ~$0.002/대화
- 100회 대화 = ~$0.20

---

## 10. Fallback 전략

프롬프트 iteration 3회 후에도 AI의 `phase` 판단이 일관되지 않으면:
- **Approach A(턴 수 기반)로 전환**: 3턴 이후 [결정할래] 버튼 노출, 6턴에서 마무리 제안
- 이건 최후의 fallback이지 목표가 아님
