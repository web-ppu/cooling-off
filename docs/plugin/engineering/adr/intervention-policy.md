## 1. 맥락 (Context)

브라우저 확장의 핵심 가치는 *모든 구매를 막는 것*이 아니라 *충동·후회 가능성이 높은 구매*에 한정해 식히는 시간을 주는 것이다. 정책이 부재하면 생필품·식료품·반복 구매에도 모달이 떠 사용자가 확장을 삭제할 위험이 크다는 리뷰어 피드백(2026-05-25)이 있었고, 이에 따라 V1 정책을 사전에 고정해야 한다.

## 2. 결정 (Decision)

PRD §7.1에 다음 네 축으로 V1 정책을 명시한다. 이 ADR은 그 결정의 근거 데이터를 담는다.

- **트리거 조건**: 바로구매·구매하기·결제 진행 버튼만. 장바구니·찜하기는 V1 제외.
- **제외 조건**: 카테고리 자동 분류는 V1 미지원(휴리스틱 false-positive 위험). 가격 기반 자동 제외는 V1 미지원(본 서비스 cooling tier가 5만원 이하도 1일 cooling을 부여하므로 "cooling 미적용 가격대"가 없음 → 임의 임계는 정책 불일치). 사용자 명시 제외 도메인·URL은 통과.
- **빈도 제한**: 동일 URL 1회 (DB unique index가 강제). 도메인 / 전역 일일 cap 없음 — 빈도는 사용자 제어로만.
- **사용자 제어권**: 사이트 on/off 토글, 24h snooze (도메인 단위, 누른 시점부터 24시간), URL skip list (영구), 전체 비활성화 (Chrome UI). 4개 컨트롤은 OR 결합 — 하나라도 매치하면 모달 안 뜸.

상세 사양은 PRD §7.1을 권위 소스로 둔다.

## 5. 대안 (Considered Alternatives)

- **트리거에 장바구니 포함**: 초안에 포함되어 있었음. 노이즈 우려로 V1에서 제외. Phase 2 후보.
- **카테고리 자동 분류 (생필품/식료품 제외)**: 휴리스틱 false-positive 리스크가 크고, 캡스톤 범위에서 신뢰할 분류기 구축 불가. Phase 2 (`TODO-7`).
- **가격 임계 게이트 (예: 10,000원 미만 통과)**: 초안에 포함되어 있었음. 본 서비스 cooling tier(`../../../pm/prd.md` §4.가격별 냉각기)가 5만원 이하도 1일 cooling을 부여하므로 "cooling 미적용 가격대"가 존재하지 않음. 임의 가격 임계는 본 서비스 정책과 불일치. V1 미지원, Phase 2 (`TODO-9`)에서 사용자가 직접 임계를 정하는 형태로 검토.
- **전역 일일 cap (예: 하루 5회)**: cap 도달 후 진짜 충동구매 시점을 놓침. 빈도는 사용자 제어권으로 우회.
- **결제 흐름 물리적 차단**: TOS 리스크 + 체크아웃 흐름 파손. P2(소프트 인터셉트)와 모순. 영구 제외.
