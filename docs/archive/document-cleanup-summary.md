# 문서 정리 요약

> 최근 문서 정리 과정에서 무엇이 바뀌었는지 팀원이 빠르게 이해하기 위한 참고 기록입니다.
> 현재 제품 기준은 [`../pm/prd.md`](../pm/prd.md)와 [`../design/screen-spec.md`](../design/screen-spec.md)를 우선합니다.

---

## 왜 정리했나

문서가 여러 번 수정되면서 과거 가설, 구현 세부, 반말 설명체, 현재 화면과 맞지 않는 정책이 함께 남아 있었습니다.

특히 다음 문제가 있었습니다.

- PRD가 팀원/교수에게 공유되는 기준 문서인데 설명체와 용어가 일관되지 않았습니다.
- 화면 정책 문서에 개발 내부 용어와 오래된 화면 정책이 남아 있었습니다.
- 로컬 저장, 자동 삭제, 실행 취소, 알림 대체 화면처럼 MVP 기준과 맞지 않거나 혼동을 주는 정책이 남아 있었습니다.
- AI 채팅 관련 문서에서 현재 프롬프트 원칙과 맞지 않는 표현이 일부 남아 있었습니다.
- README에 현재 저장소에 없는 프로토타입 실행/배포 안내가 남아 있었습니다.

## 주요 변경

- 제품을 네이티브 앱이 아니라 **반응형 웹 서비스** 기준으로 정리했습니다.
- MVP부터 **로그인 기반 영구 저장**을 전제로 정리했습니다.
- 등록 필드는 **이름, 가격, URL, 사고 싶은 이유** 기준으로 통일했습니다.
- 냉각 중 화면은 **물건 이름, 남은 시간, 결정 가능 시점**만 보여주는 대기 화면으로 정리했습니다.
- 냉각 종료 후에는 홈의 **결정 대기 섹션**에서 AI 채팅으로 진입하는 흐름으로 정리했습니다.
- AI 채팅은 **현재 등록 정보와 현재 대화에서 나온 사실만 사용**하도록 정리했습니다.
- 시스템 UI, 오류, 로그인, 저장 안내는 존댓말을 사용하고, **AI 채팅만 짧고 직설적인 반말**을 쓰는 것으로 정리했습니다.
- 기록은 [삼]/[안 삼]으로 확정한 결정만 보여주고, 완료 기록도 사용자가 삭제할 수 있도록 정리했습니다.
- 알림은 결정 대기 항목을 확인하게 돕는 보조 수단으로 정리했습니다.

## 제거하거나 축소한 내용

- 실행 취소 정책
- 48시간 자동 삭제 정책
- 등록 직후 취소 안내
- 알림 수신 여부를 기준으로 한 대체 화면 설명
- 기획 문서 범위를 벗어나는 상세 DB/Auth/ERD/API 설계
- `Decide`, `phase`, `gathering`, `closing` 같은 내부 진행 상태 용어
- 상품 이미지 사용 정책
- 절약 금액, 안 삼 비율, 스트릭, 배지 같은 게이미피케이션 요소
- 현재 저장소에 없는 프로토타입 로컬 실행/배포 안내

---

## 팀원이 확인하면 좋은 부분

1. PRD의 MVP 범위와 화면 정책이 맞는지
2. 로그인 기반 저장과 비로그인 접근 정책이 과제 범위에 맞는지
3. 냉각 중 화면에서 가격, URL, 사고 싶은 이유를 숨기는 정책이 제품 의도와 맞는지
4. AI 채팅 말투와 [결정하기] 버튼 표시 기준이 자연스러운지
5. 기록 삭제 허용 정책이 팀의 기대와 맞는지
6. 알림을 MVP에 포함하는 범위가 적절한지
