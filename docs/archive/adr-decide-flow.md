# ADR — Decide 플로우 재설계 (AI 대화 종료 + 결정 버튼 노출)

## 1. 맥락

기존 스펙(`ai-prompt-v1.md` v0.2)에 AI 대화 종료 경로가 3개 있었다:
1. AI가 `[END]` 토큰 발동 (사용자 자각 감지 시)
2. 사용자가 "결정하러 갈게" ghost 버튼 누름
3. Hard cap 10턴/cold start 5턴

문제: **세 경로 모두 근거 없이 설정됨.** 턴 수 기반 접근은 대화 품질/맥락과 무관하고, [END] 토큰 발동 조건도 모호했다. Phase A(대화) → Phase B(결정)가 별도 화면으로 전환되는 구조도 맥락 단절 문제가 있었다.

**결정**: 기존 스펙을 전면 폐기하고, 과학적 근거와 시뮬레이션 기반으로 백지에서 재설계.

## 2. 최종 결정 — 4단계 Decide 플로우

```
① AI 대화
   정보 수집 (phase: gathering)
   → AI가 수집한 정보를 가공하여 관점 제시 (phase: perspective)
   → [결정할래] 버튼 노출
   → 대화 계속 가능 (버튼은 유지)
   → AI가 충분하다 판단 시 "결정할 준비 됐어?" 제안 (phase: closing)
   → Hard cap 10턴 도달 시 AI가 맥락 인지 마무리 + 입력창 비활성화

② [결정하기] 버튼 누름

③ 팩트 요약 카드
   지금까지 대화에서 나온 사실만 bullet으로 정리
   AI 판단/조언 없음

④ [안 삼] / [삼] 대칭 버튼 → 홈
```

핵심: **대화와 결정 버튼이 같은 화면에 공존.** 별도 화면 전환 없음. 버튼이 나타난 후에도 대화를 계속할 수 있고, 준비되면 결정.

## 3. 합의된 전제

| # | 전제 | 근거 |
|---|------|------|
| 1 | AI 대화 목적 = 사용자 스스로 객관적으로 보고 합리적 소비인지 깨닫게 하는 것 | PRD 원칙 "informed decision" |
| 2 | 결정 버튼 노출 트리거 = AI가 수집한 정보를 가공해서 새로운 관점을 1회 이상 제시한 후 | 정보 수집(구체화 질문)만으로는 사용자가 아무것도 깨달은 게 없음. AI가 "35만원어치 귀찮음"처럼 정보를 가공해서 돌려줘야 객관화가 시작됨 |
| 3 | 대화와 결정 버튼 공존 = 같은 화면, 별도 전환 없음 | 화면 전환은 대화 맥락 단절. one sec 연구의 "선택권" 원칙 — 버튼이 있으면서 대화도 가능한 상태 |
| 4 | 대화 마무리 = AI가 맥락 판단. 턴 수 고정 없음 | 세컨드 오피니언 지적: "3만원짜리 텀블러와 300만원짜리 카메라에 같은 5턴 적용은 비합리적." 합리적 구매는 2턴에 통과, 충동구매는 더 길게 |
| 5 | Hard cap 10턴 = API 비용 방어. AI가 맥락 인지하여 자연스럽게 마무리 | 10턴 넘으면 AI 반복 → 신뢰 깨짐 + 결정 피로. 기계적 종료가 아니라 AI가 대화 맥락 보고 마무리 멘트 생성 |
| 6 | 결정 직전 팩트 요약 = [결정할래] 누르면 항상 표시. 팩트만, 판단 없이 | Recency bias 방어. 대화 초반 핵심 지적이 묻히는 거 방지. 기존 Phase B의 "대화 전체 scroll"보다 소화하기 쉬움 |
| 7 | MVP AI 반박 = specificity + reality_check만 | Cold start 문제. 학교 팀플 발표(6/13) 시연 사용자는 대부분 첫 사용자라 history 없음. History 기반(past_pattern, contradiction)은 Phase 2 |

## 4. 기각된 대안

| 대안 | 기각 이유 |
|------|----------|
| **턴 수 기반 (soft target 5~6턴)** | 대화 품질과 무관. 합리적 구매자에게 불필요한 대화 강제 → 짜증 → 앱 삭제. 세컨드 오피니언에서도 "가장 틀린 전제"로 지적 |
| **결정 버튼 상시 노출 (1턴 후)** | AI 대화 우회 가능 → 앱 차별점(AI 대화) 소멸. CutCut과 다를 게 없어짐. 자기구속장치 원칙 위배 |
| **시간 기반 (N초 후)** | 시간은 대화 품질과 무관. 90초 동안 의미 없는 대화해도 버튼 뜸 |
| **점점 선명해지는 버튼** | 사용자가 흐린 버튼 눌러서 관점 제시 없이 결정 가능 → 자기구속장치 위배 |
| **버튼 없이 대화로 결정** | "살래" 자연어 인식의 LLM 파싱 의존도 너무 높음. "살까..." "사야겠다" 같은 애매한 표현 오판 리스크 |
| **"구체화 1회" 기반 트리거** | 처음에 이 방향이었으나, 시뮬에서 "하루에 한번 충전해"는 구체적 답변이지만 사용자가 아무것도 깨달은 게 아님을 발견. 정보 수집 ≠ 관점 제시 — 단계가 다름 |

## 5. 세컨드 오피니언 핵심

독립 AI(이 대화를 안 본 상태에서 문제+전제만 보고 평가)의 핵심 지적:

> "진짜 풀어야 할 건 '이 사용자가 자기 rationalization을 인식했는가'의 신호다 — 턴 수가 아니라 상태 기반."

> "Soft target 5-6턴이 틀렸다. 사용자가 1턴 만에 자각하면 나머지 4턴은 순수한 짜증이 된다."

이 지적이 "턴 수 고정 폐기 → AI 맥락 판단 기반"으로의 전환을 확정시킴.
