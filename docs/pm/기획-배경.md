## Phase 1: Problem Framing Canvas

### 누구의 어떤 문제인가?

**타겟 사용자**: 한국 20~30대 MZ세대, 특히:
- 모바일로 쇼핑하는 사람 (한국 온라인쇼핑의 76%가 모바일)
- SNS 광고 경유 구매가 잦은 사람 (20대 44%가 SNS 광고 보고 구매 경험)
- 쿠팡 와우 멤버십 사용자 (비회원 대비 2.5배 지출)
- 자기통제력이 낮다고 느끼는 사람 / ADHD 경향이 있는 사람

**핵심 문제**: "사고 싶다"에서 "결제 완료"까지의 거리가 극도로 짧아서, 충동구매 후 후회하는 사이클이 반복된다.

### 문제의 크기 (데이터)

| 지표 | 수치 | 출처 |
|------|------|------|
| 월 평균 충동구매 | $282 (약 37만원) | Capital One Shopping 2024 |
| 충동구매 후회율 | 56~68% | SimplicityDX, Bankrate |
| MZ세대 후회율 | 70%+ | Finder |
| SNS 경유 구매 후회율 | 68% | Bankrate |
| "필요 없었다" + "감당 못할 금액" | 42% | SimplicityDX |

### 왜 지금인가? (환경 변화)

1. **한국 이커머스 인프라가 충동구매를 극한까지 촉진**: 쿠팡 MAU 3,240만, 로켓배송 "내일 도착", 새벽배송 시장 30배 성장(4,000억→11.8조)
2. **BNPL 급성장**: 연평균 34.1% CAGR, 할부 프레이밍이 가격 인지를 왜곡
3. **무지출 챌린지 트렌드**: 미국 성인 25%가 경험, 한국 80.7%가 "꼭 필요한 것만 산다"고 응답 — 소비 절제에 대한 사회적 수요가 있다
4. **모바일 네이티브 냉각기 앱이 한국에 없다**: Icebox는 Chrome 전용, CutCut은 한국어 미지원

### 근본 원인 분석 (뇌과학 기반)

리서치가 보여주는 충동구매의 메커니즘:

```
[트리거]                    [뇌 반응]                              [결과]
SNS 광고 / 리뷰 브라우징 → 측좌핵(NAcc, "이거 갖고 싶다" 신호) 활성화  → "갖고 싶다"
                         → 도파민 피크 (기대하는 순간이 가장 강함)
가격 확인               → 뇌섬엽(insula, 불쾌감/고통 영역) 활성화     → "좀 비싼데..."
                         → 신용카드/BNPL이 이 고통을 제거
결정                    → MPFC(내측 전전두엽, 이득 vs 손실 저울질)가 판단
                         → 근데 퇴근 후 PFC(전전두엽, 이성적 판단 담당)가
                           고갈된 상태라 감정(변연계, 본능적 반응 담당)이 압승
구매 완료               → 만족(liking) < 기대(wanting) → "이게 이 정도였어?"
                         → 소유 효과(내 거가 되면 가치를 높게 평가) 발동 → 취소 안 함
후회                    → 다음 충동에서 반복
```

**핵심 인사이트**: 뇌가 결정을 먼저 끝낸다. 자기보고("이건 필요해")보다 뇌 활동이 구매를 더 정확하게 예측한다 (Knutson 2007, 60% 정확도). "필요한가?"라는 질문은 이미 늦었다.

### 기존 해결책이 실패하는 이유

| 접근 | 왜 부족한가 | 근거 |
|------|------------|------|
| 전통 쿨링오프 (사후 취소) | 소유 효과 + 현상 유지 편향 + 일관성 이론 → 거의 아무도 취소 안 함 | Harrison & Newton 2016, 759명 |
| 숙고 메시지 ("생각해보세요") | 독립적 효과 없음 | one sec PNAS 연구, 500명 통제실험 |
| 벌금형 앱 (챌린저스, stickK) | 모든 사람에게 작동하지 않음, 크라우딩 아웃 효과 | HBR 병원 연구 |
| 가계부 앱 (토스, 뱅크샐러드) | "산 후" 추적이지 "사기 전" 개입이 아님 | — |
| 장바구니에 넣고 기다리기 | 쇼핑몰별 파편화, 대기 기간 강제 불가, 알림 없음 | 커뮤니티 리서치 |

## Phase 2: 증거 수집

### 이미 확인된 사용자 행동 (커뮤니티 리서치 기반)

사람들이 **자발적으로** 하고 있는 workaround Top 5:

1. **장바구니에 넣고 안 사기** — 72시간 규칙, Google Doc에 적기. "80~90%가 며칠 뒤 사라진다"
2. **쇼핑 마찰 높이기** — 결제정보 삭제, 쇼핑앱 삭제, 마케팅 알림 차단
3. **자기 질문법** — "이 물건이 원하는 거야, 이 돈이 원하는 거야?"
4. **거지방 (사회적 책무)** — 카톡 오픈채팅에서 서로 소비 감시
5. **무지출 챌린지** — 기간 자체를 소비 금지 구간으로 선언

### 검증이 필요한 핵심 가정

| # | 가정 | 리스크 수준 | 현재 근거 |
|---|------|-----------|----------|
| A1 | MZ세대가 충동구매를 문제로 인식하고 해결 의지가 있다 | 중 | 무지출 챌린지 트렌드, 거지방 문화 (간접 근거) |
| A2 | "사기 전 냉각기"가 "산 후 추적"보다 효과적이다 | 낮음 | Harrison opt-in 연구, one sec PNAS 연구 (강한 근거) |
| **A3** | **사용자가 쇼핑 흐름 바깥의 별도 앱에 물건을 등록하는 마찰을 감수한다** | **높음** | **근거 없음 — 가장 큰 리스크** |
| A4 | 소셜 기능(친구 공유, 투표)이 retention에 핵심이다 | 중 | 거지방 문화 (간접), 사회적 책무감 연구 (이론적) |
| A5 | 구독 모델이 아닌 다른 수익 구조가 가능하다 | 높음 | Stop Impulse Buying의 구독 역설 (반례) |

> **A3이 가장 위험하다.** 쿠팡에서 "구매하기"를 누르기 직전에 별도 앱으로 이동해서 등록하는 건 엄청난 마찰이다. 이 마찰이 "의도적으로 원하는 마찰"인지, "짜증나서 안 쓰는 마찰"인지가 앱의 생존을 결정한다.

## Phase 3: Opportunity Solution Tree

### 목표 성과

- **사용자**: 충동구매를 줄이고, 후회 없는 소비를 한다
- **비즈니스**: 지속 가능한 수익 모델로 사용자를 유지한다

### 기회 영역

```
[목표] 충동구매 후회 감소
├── O1. 구매 전 "멈춤"을 만든다
│   ├── O1.1 시간 장벽 (냉각기)
│   ├── O1.2 인지적 마찰 (질문/체크리스트)
│   └── O1.3 디지털 마찰 (앱 접근 지연)
├── O2. 편향을 벗겨낸다
│   ├── O2.1 기회비용 환기 ("이 돈이면 대신 뭘?")
│   ├── O2.2 자기거리두기 ("친구한테 뭐라고 할 건데?")
│   ├── O2.3 반대 사유 생성 ("사지 말아야 할 이유 3가지")
│   └── O2.4 시간적 거리두기 ("6개월 후에도 쓸까?")
├── O3. 사회적 힘을 활용한다
│   ├── O3.1 친구와 위시리스트 공유
│   ├── O3.2 "이거 사도 돼?" 투표
│   └── O3.3 거지방 라이트 (소비 스터디)
├── O4. 성취감을 게이밍한다
│   ├── O4.1 절약 금액 누적
│   ├── O4.2 참은 횟수 스트릭
│   └── O4.3 무지출 챌린지 모드
└── O5. 감정 패턴을 발견하게 한다
    ├── O5.1 감정 태깅 ("지금 왜 사고 싶어?")
    └── O5.2 구매 충동 패턴 리포트
```

### 솔루션 옵션

#### Solution A: "위시리스트 + 냉각기 + 체크리스트" (핵심 루프) ← MVP 후보

**작동 방식**:
1. 사고 싶은 물건 발견 → 앱에 등록 (상품명, 가격, URL)
2. 가격별 자동 냉각기 시작 (기본 24시간, 가격별 조정)
3. 냉각기 동안 — 알림 없음, 조용히 대기
4. 냉각기 종료 → 푸시 알림 "아직도 원해?"
5. 7개 질문 체크리스트 표시 (각각 특정 편향 겨냥)
6. 사용자 선택: [구매하기] or [포기하기]
7. 아무것도 안 하면 → 자동 삭제 (default = 안 삼)

**과학적 근거**:
- opt-in 방식 (Harrison 2016): 소유 효과 전에 개입
- 마찰 + 선택권 (one sec PNAS 2023): dismiss 옵션이 가장 효과적
- 7개 질문: Frederick(기회비용), Grossmann(솔로몬 역설), Croskerry(디바이어싱) 근거
- default "안 삼": 냉각기 한계 연구의 제안

#### Solution B: "쇼핑 앱 마찰 레이어" (one sec 쇼핑 버전)

쿠팡, 네이버쇼핑 등 쇼핑 앱을 열 때 10초 대기 + "정말 열겠습니까?" + "그만두기" 옵션.
- one sec이 이미 이걸 하지만, 상품 단위가 아니라 앱 단위
- 쇼핑 앱 열기 자체를 줄이는 효과 (6주 뒤 57% 감소)

#### Solution C: "소셜 냉각기" (거지방 + 위시리스트)

친구들과 위시리스트 공유, "이거 사도 돼?" 투표, 결과가 냉각기 동안 표시.
- 사회적 책무감 연구: 평판 동기가 금전 인센티브보다 장기 효과 우월

## Phase 4: 검증 프로브 설계

> **참고**: 아래 Probe 1~3은 원래 디스커버리 단계에서 가설을 검증하기 위한 계획이다. 학교 팀플(2개월)이므로 이 검증 단계는 스킵하고, 효과가 있다는 전제로 바로 MVP 개발에 들어간다. PRD(`docs/prd.md`)가 실제 구현 범위를 정의한다. 아래는 "원래 검증하려면 이렇게 했을 것"이라는 기록용이다.

### Probe 1: 랜딩 페이지 + 대기자 등록 (1주)

**목적**: "충동구매를 막아주는 앱"에 수요가 있는지 확인
- 한 줄 가치 제안: "사고 싶은 거, 일단 여기 넣어. 7일 뒤에도 원하면 그때 사."
- 이메일/전화번호 수집
- **성공 기준**: 200명 방문 중 15%+ 등록 (30명+)

### Probe 2: 초경량 웹앱 프로토타입 (2주)

**목적**: A3 검증 — 실제로 물건을 등록하고 냉각기를 지키는지
- 핵심 기능만: 상품 등록 (이름+가격+URL) → 냉각기 자동 → 알림 → 체크리스트 → 구매/포기
- 소셜 기능 없음, 게이밍 없음 — 핵심 루프만 테스트
- **성공 기준**:
  - 등록 후 냉각기 완료까지 도달률 50%+
  - 냉각기 후 "포기" 선택률 30%+
  - 7일 리텐션 20%+

### Probe 3: 체크리스트 효과 A/B 테스트 (Probe 2 이후)

**목적**: 7개 질문 체크리스트가 단순 "아직도 원해?" 대비 포기율을 높이는지
- A: 냉각기 후 "구매하기 / 포기하기" 버튼만
- B: 냉각기 후 7개 질문 체크리스트 → "구매하기 / 포기하기"
- **성공 기준**: B의 "포기" 선택률이 A보다 15%p+ 높음

## Phase 5: 실행 계획 종합

### 지금 만들 것 (MVP): Solution A의 핵심 루프

Phase 3에서 정의한 Solution A를 그대로 MVP로 가져간다. 구체적인 기능 목록, 화면 구성, 유저 스토리는 **PRD(`docs/prd.md`)**에 정리되어 있다.

### 이름

"쿨링오프" — 태그라인 "사기 전에 한 번 식히기"
- 인지도 16.8%이지만, "쿨링"이 한국에서 충분히 친숙하고 컨셉과 완벽히 맞음
- 서브타이틀로 보완 필수

### 핵심 설계 원칙 (리서치에서 도출)

| 원칙 | 근거 |
|------|------|
| **"사후 취소"가 아니라 "사전 확인"** | Harrison 2016: 소유 효과 전에 개입해야 함 |
| **Default = "안 삼"** | 아무것도 안 하면 자동 삭제. 능동적으로 "살래"를 눌러야 구매 |
| **마찰 + 선택권** | one sec PNAS: dismiss 옵션이 가장 효과적, 숙고 메시지 단독 효과 없음 |
| **"필요한가?"가 아니라 "기다려도 원하는가?"** | Knutson 2007: 뇌가 이미 결정 완료 상태에서 "필요한가?"는 합리화만 유발 |
| **편향별 구조화된 질문** | Frederick(기회비용), Grossmann(솔로몬 역설), Croskerry(디바이어싱) |
| **최소 24시간 (sleep on it)** | Duke 2024: 하룻밤이 첫인상 편향 감소. 최적 기간은 학술적으로 미확인 → A/B 테스트로 검증 |
| **판단을 강요하지 않기** | 체크리스트 후에도 사겠다면 사는 거. "informed decision"이 목적 |

> 이후 여러 차례 재설계를 거쳤고, 최종적으로 2026-04-12 LLM chat pivot에서 정적 체크리스트 자체를 폐기함.

>
> **폐기 근거**:
> - 정적 체크리스트는 합리화형 사용자에게 motivated reasoning으로 우회됨

## Phase 6: 명시적 설계 결정 (PRD 보강 근거)

PRD(`docs/prd.md`)는 "무엇을 / 어떻게"만 다루고, "왜 그렇게 결정했는지"는 이 섹션에 정리한다. PRD를 구현하다가 "이게 왜 이래?" 싶을 때 여기로 와서 확인하면 된다.

### 6-1. 왜 예산 관리/잔액 표시 기능을 뺐는가?

"남은 예산을 보여주면 절약에 도움 되겠지"라는 직관과 반대되는 연구가 있다.

University of Arizona의 **Pocheptsova Ghosh & Huang** 연구에서, 예산 앱으로 잔액을 정확히 아는 소비자가 **최대 33% 더 많이** 지출했다. 메커니즘은 이렇다:
- 잔액을 모르면 "혹시 초과할까 봐" **안전마진**을 쌓는다
- 정확히 알면 "아직 이만큼 남았네" → 끝까지 소진

Irrational Labs의 **9,035명 RCT**(무작위 대조 실험)에서도 예산 설정이 지출 감소에 **유의한 효과가 없었다** (p>0.4, 즉 "우연일 수 있다"는 뜻).

그래서 쿨링오프 앱은 예산 기능 대신 **"포기한 물건의 절약 금액 누적"**만 보여준다. 이건 "남은 돈"이 아니라 "아낀 돈"이니까 안전마진 제거 문제가 발생하지 않는다. 프레이밍이 반대 방향이다.

> 관련: [[예산 앱 역효과 — 안전마진 제거 (Budgeting App Trap)]], [[사후 지출 추적의 충동구매 감소 효과 리서치]]

### 6-2. 톤 & 프레이밍 — "판사가 아니라 친구"

쿨링오프 앱의 목적은 **"안 사게 만드는 것"이 아니라 "정보에 기반한 결정(informed decision)"**이다. 이 원칙이 톤과 카피 전반에 영향을 준다.

- "이거 진짜 필요해?" (심문) → **X**
- "기다렸는데 아직도 끌려?" (대화) → **O**

**이유 1: "필요한가?"는 틀린 질문이다.** Knutson (2007) fMRI 연구에서, 사람이 "이건 필요해"라고 느끼는 순간 뇌가 이미 감정적으로 결정을 끝낸 상태였다. "필요한가?"를 물으면 합리화만 나온다. **"기다려도 원하는가?"**가 더 정직한 질문이다.

**이유 2: 죄책감은 이탈을 부른다.** 체크리스트를 다 거치고도 사겠다면 그건 합리적 구매다 — 앱이 막으면 안 된다. "포기"에 과도한 보상을 주면 필요한 것도 안 사게 되는 역효과가 나고, 죄책감을 유발하면 사용자가 앱을 끈다.

**적용:**
- 체크리스트 마지막 버튼은 [포기]와 [구매]가 **동일한 시각 비중** (어느 쪽이 "맞는 답"이라고 암시하지 않음)
- 포기 후 피드백: "잘 참았어!" 같은 과장 칭찬 금지, 건조하게 "기록에 남았어요" 수준
- 구매 후 피드백: "진짜 사네?" 같은 비꼬는 톤 금지, "구매 결정됨" 중립적으로

> 관련: [[충동구매의 뇌과학 (Impulse Buying)]], [[구매 결정의 신경 예측 (Neural Predictors of Purchases)]]

### 6-3. 기술 스택 선택 근거

> 이 섹션은 초기 디스커버리 당시의 기술 가설이다. 현재 PRD는 구체 Auth/DB/PWA 구현 방식을 확정하지 않는다. 구현 선택은 `../engineering/tech-spec.md`에서 개발자가 결정한다.

당시 기술 스택 후보(Next.js + React + Tailwind CSS + Supabase + Vercel + next-pwa)는 다음 세 제약을 동시에 만족하는 조합으로 검토했다.

**제약 1: 수업 요구사항**
- 웹프로그래밍 수업이라 **React + Next.js가 고정**. 이 조건이 가장 강한 제약이다.

**제약 2: 개발 기간 부족**
- 실질 개발 기간 3주(5월 W5~W7). 바이브코딩(AI 보조 개발) 전제.
- 백엔드는 **최대한 빠르게 구현 가능한 스택**이 필요하다고 보고 Supabase를 후보로 검토
  - PostgreSQL + Auth + API 자동 생성
  - 비개발자가 대시보드에서 테이블 만들면 즉시 API 사용 가능
  - Firebase보다 구조 직관적, SQL 기반이라 디버깅 쉬움
- Tailwind CSS: CSS 파일 분리 없이 클래스 하나로 스타일링 + 반응형 자동 (`md:` breakpoint). 바이브코딩과 궁합 최상.

**제약 3: 반응형 + PWA + 푸시 알림 필요**
- `next-pwa` 패키지로 manifest.json + Service Worker 세팅 가능
- Web Push API로 브라우저 푸시 알림 (iOS 16.4+ Safari 지원)
- Next.js + Vercel 조합이라 배포도 `git push`로 자동

**당시 결론**: 이 조합이면 MUST 전체를 3주 안에 완성 가능하고, 수업 취지(프론트엔드 중심)도 만족한다고 판단했다. 현재 구현 방식은 tech-spec에서 재확정한다.

**팀 상황 고려 요소:**
- 개발 2명 중 비개발자 포함 → 복잡한 백엔드 아키텍처 금지
- 디자이너 2명 → 디자인 핸드오프 툴(Penpot or Figma)과 React 코드 연결 쉬워야 함
- 발표 시연 → Vercel URL 하나로 PC/모바일 둘 다 접근 가능해야 함
