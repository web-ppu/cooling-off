## 1. 한 줄 요약

쿨링오프는 "원함(wanting)"의 도파민 스파이크와 실제 결제 사이에 시간과 대화를 넣어서, "좋아함(liking)"을 미리 예상해볼 수 있게 만드는 마찰형 자기구속장치(Commitment Device)야.

---

## 2. 타겟 사용자

### Primary — 합리화형 충동구매자 (MZ)

"이거 사면 더 나은 내가 될 거야" 류의 미래 자아 환상에 취약한 사람.

- 생산성 도구, 전자기기, 자기계발 소비에 약함
- "실용적이야" / "3년은 쓸 거야" / "일당 계산하면..." 같은 자기설득 패턴
- 나중에 돌이켜보면 "그때 그거 충동이었네" 인정할 수 있는 사람
- 명품이나 수집 같은 소비는 안 함

### 타겟 아님

| 타입 | 배제 이유 |
|------|----------|
| 과시형 / 멍청소비 | 충동을 문제로 인식 안 함 |
| 수집가 / 덕질 | "실용" 개념 무의미 |
| 생활비 낭비형 | 한 번의 "결정 시점"이 없음 |
| 쇼핑중독 (임상) | 치료 영역. 앱이 다루면 위험함 |

### Positioning vs Usage

포지셔닝은 합리화형으로 좁게 잡되, 실제 가입과 사용은 누구나 가능하게. Crossing the Chasm 원칙.

---

## 3. 왜 이 앱이어야 하나

### "갖고 싶다"와 "좋아한다"는 다른 감정이야

사기 전 흥분이 산 후 만족보다 항상 크거든. 뇌에서 wanting과 liking은 아예 다른 회로야. 시간이 지나면 wanting이 식고, 그때 다시 판단하면 더 정확해.

### 체크리스트 같은 자기 점검은 안 먹혀

자기가 쓴 답을 자기가 검토하는 구조라, "실용적이야"로 스스로를 설득하는 사람한테 뚫려. 체크리스트든 숙고 메시지든 같은 한계가 있어.

### 남의 문제는 잘 보이는데 내 문제는 못 보거든

심리학에서 Solomon의 역설이라고 불러. 자기 문제엔 형편없는데 타인 문제엔 현명한 현상. 외부 관찰자와의 대화가 이 gap을 뚫는 유일한 방법이야.

### 결정 기록을 다시 볼 수 있어

앱은 사용자가 전에 뭘 등록하고 어떻게 결정했는지 기록을 보존해. 사용자는 나중에 자신의 결정 흐름을 다시 볼 수 있어.

## 4. 원칙

1. **사전 확인** — 산 다음에 취소하게 하는 게 아니라, 사기 전에 한 번 멈추게 해. 이미 내 거가 된 다음엔 취소를 잘 안 하거든.
2. **default = 삭제** — 아무것도 안 하면 자동 삭제. "사겠다"를 적극적으로 선택해야만 구매 결정이 됨.
3. **절약 금액 안 보여줌** — "N원 절약했어!" 같은 숫자 안 보여줘. 그 숫자 올리는 게 목적이 되면 필요한 것도 안 사게 되니까. 스트릭/뱃지도 같은 이유로 없어.
4. **대칭 버튼** — [안 삼]/[삼] 버튼이 똑같은 크기, 똑같은 색. 어느 쪽이 정답이라고 유도 안 해. 과장 칭찬이나 비꼼도 없음.
5. **AI는 짧고 직설적인 반말** — AI 채팅에서만 반말을 쓴다. 친근한 수다체가 아니라, 외부 관찰자가 사실과 질문을 짧게 던지는 말투다. 시스템 UI, 입력 검증, 오류, 로그인, 저장 안내는 짧고 중립적인 존댓말을 쓴다.
6. **짧은 등록** — 등록은 복잡한 단계 없이 이름, 가격, URL, 왜 사고 싶은지 한 줄이면 됨.
7. **냉각기 중 정보 숨김** — 냉각기 동안은 물건 정보를 일부러 안 보여줘. 다시 보면 "역시 사야 해" 생각이 되살아나니까.
8. **AI = 팩트 반박자** — AI는 "사지 마"라고 말하지 않아. 현재 등록 정보와 현재 대화에서 나온 사실을 바탕으로 질문만 던지고, 최종 결정은 항상 사용자.

## 5. 사용 흐름 + 냉각기 테이블

### 사용 흐름 (6단계)

```
① 등록 (단일 폼)
   ↓ 봉인 애니메이션
② 봉인·냉각 (가격별 5-tier 타이머)
   ↓ 냉각기 만료
③ 홈 최상단 픽업 카드 (warm amber)
   ↓ 카드 탭
④ AI 대화 + [결정하기] 버튼
   ↓ [결정하기] 탭
⑤ 팩트 요약 + [안 삼]/[삼]
   ↓
⑥ 기록 (결정 N개 중립 카운트)
```

### 가격별 냉각기

| 가격 | 기간 |
|------|:---:|
| ≤ 5만원 | 1일 |
| 5~10만원 | 2일 |
| 10~30만원 | 7일 |
| 30~100만원 | 14일 |
| 100만원+ | 30일 |

## 6. 기능 요구사항

### FR-1. 상품 등록 (단일 폼)

단일 페이지 폼, 4 필드. Wizard나 step progress 없음.

1. **이름** (필수)
2. **가격** (필수, 입력하면 냉각기 기간이 바로 보여)
3. **URL** (선택)
4. **"왜 사고 싶어?"** free text 1~3줄 (선택이지만 강하게 권장)
   - 서브카피: "나중에 다시 볼 이유예요"

완료 시 봉인 애니메이션 → 홈 이동.

### FR-1A. 로그인 및 데이터 저장

MVP부터 사용자 데이터는 계정에 연결된 영구 저장소에 저장한다. 결정 기록은 사용자가 나중에 다시 볼 수 있어야 하므로, 브라우저 삭제로 기록이 날아가는 구조를 기본값으로 두지 않는다.

- 로그인 방식은 MVP에서 가장 간단한 1개 방식만 제공한다.
- 비로그인 사용자는 About 확인과 로그인 진입만 가능하다.
- 실제 등록, 냉각, Decide, 기록 열람은 로그인 후 가능하다.
- 등록 상품, 결정 결과, AI 대화 기록은 계정에 연결된 영구 저장소에 저장한다.
- 데이터는 사용자별로 분리되어야 하며, 다른 사용자의 기록이 노출되면 안 된다.
- 브라우저 로컬 저장소는 폼 draft, 토스트 같은 임시 UI 상태에만 쓴다. 영구 데이터 저장소로 쓰지 않는다.

### FR-2. 냉각기 (가격별 5-tier)

가격 기반 자동 배정. 냉각기 중에는 상품명, 가격, URL 전부 비노출 — 타이머만 보여줌.

- 냉각 중 항목은 삭제 가능. 잘못 등록했거나 더 이상 필요 없어진 항목을 정리할 수 있어야 한다.
- 삭제된 냉각 중 항목은 홈 목록에서 사라지고 기록에는 남기지 않는다.
- 결정이 완료된 기록은 삭제하지 않는다.

### FR-3. Decide 플로우 (4단계, 단일 화면)

냉각기가 끝난 아이템의 픽업 카드를 탭하면 시작. **대화와 결정이 같은 화면에서 진행.** 별도 화면 전환 없음.

```
① AI 대화
   정보 수집 → AI가 관점 제시 → [결정하기] 버튼 노출 → 대화 계속 가능
② [결정하기] 버튼 누름
③ 팩트 요약 카드 (사실만, 판단 없이)
④ [안 삼] / [삼] 대칭 버튼
```

- **정보 수집 단계**: AI가 등록 사유를 바탕으로 구체화 질문을 던짐. 이 단계에서는 결정 버튼 미노출.
- **관점 제시 이후**: AI가 수집한 정보를 가공해서 새로운 관점을 제시하면(산수, 대안, 모순 등) [결정하기] 버튼 노출. 대화는 계속 가능.
- **AI 마무리 제안**: AI가 충분하다고 판단하면 "결정할 준비 됐어?"라고 대화로 물어봄. 턴 수 고정 없음 — 합리적 구매는 2턴에 통과, 충동구매는 더 길게.
- **Hard cap 10턴**: API 비용 방어. AI가 맥락 인지하여 자연스럽게 마무리 + 입력창 비활성화.
- **팩트 요약**: [결정하기] 누르면 대화에서 나온 사실을 bullet으로 정리해서 보여줌. AI 판단 없이.
- **결정**: [안 삼] / [삼] 대칭 버튼. 탭하면 즉시 기록으로 확정.

> 상세 의사결정 근거: `../archive/adr-decide-flow.md`
> AI-프론트엔드 인터페이스: `../engineering/ai-frontend-contract.md`
> AI 대화 시뮬레이션: `../engineering/ai-simulation-log.md`

### FR-4. 결정

[안 삼] / [삼] 탭 → 즉시 기록. 중립 라벨 — "포기"/"구매" 같은 편향된 용어 안 씀.

### FR-5. 홈 (재방문 픽업존)

- 결정 대기 섹션이 최상단 고정 (warm amber)
- 냉각 중 섹션은 하단 (cool tone)
- 하단 고정 주요 버튼 "+ 사고 싶은 물건 등록"
- 빈 상태: "사고 싶은 물건이 있나요?"

### FR-6. 기록 (결정의 궤적)

- "지금까지 내린 결정 N개" 중립 카운트
- 월별로 묶여서 나옴
- 각 카드 누르면 당시 AI랑 나눈 대화를 다시 읽을 수 있어
- 라벨은 "삼" / "안 삼"
- **금지**: 절약 금액 합산, 포기율, 스트릭

### FR-7. Blank Waiting (냉각기 중 접근)

타이머만 보여주고, 상품 정보 전부 비노출. "사지 마세요" 같은 설득 카피도 없음. 그냥 조용히 기다려.

### FR-8. About 페이지

앱 정체성(wanting vs liking, commitment device), 과학 근거 요약, 사용법 요약, 주의 문구(데이터 저장/계정 정책 + 쇼핑중독 면책).

### FR-9. 돌아옴 메커니즘

- 냉각기가 끝나면 사용자에게 알림을 제공한다.
- 사용자가 앱을 열면 남은 시간 또는 결정 가능 상태가 정확히 표시된다.
- 알림은 웹 기술 스택 안에서 제공한다.
- 알림 권한이 없거나 사용자의 브라우저/OS에서 지원하지 않는 경우에도, 앱 안에서는 결정 가능 상태를 명확히 보여준다.
- 알림 구현 방식은 개발 설계에서 결정한다.

### FR-10. AI Chat Layer

Decide 단계의 핵심 메커니즘. 정적 체크리스트는 합리화형에 바이패스되니까, full-screen multi-turn chat으로 전환한 거야. 상세 프롬프트 설계는 `../engineering/ai-prompt-v1.md` 참조.

## 7. AI 대화 컨셉

### 시작

항상 같은 질문: "네 말 들어볼게. 왜 이거 지금 사고 싶어?"

### AI가 반박하는 4가지 방법

매 턴마다 AI가 현재 등록 정보와 현재 대화에서 가장 강한 증거가 있는 방법을 골라:

- **추상적 → 구체 숫자 요구**. "매일 쓴다고? 지난 2주 몇 번?"
- **모순 지적**. 등록할 때 적은 이유랑 지금 말이 다르면 지적
- **산수**. 숫자를 말하면 산수를 해줌. "주 2번이면 월 8번, 89만원 ÷ 8 = 한 번에 11,000원"

### AI가 절대 안 하는 것

- "사지 마" 같은 지시
- "낭비야" 같은 도덕 평가
- "예산부터 세워봐" 같은 일반 조언
- 과도한 공감
- 기록에 없는 사실 지어내기
- 최종 결정 내리기

### 결정으로 넘어가기

세 가지 경우:

1. AI가 관점을 제시하면 [결정하기] 버튼이 노출된다.
2. 사용자가 [결정하기]를 누르면 대화 입력창이 사라지고 팩트 요약으로 넘어간다.
3. 최대 10턴에 도달하면 AI가 맥락을 보고 마무리하고, 추가 입력은 비활성화된다.

## 8. 성공 메트릭

### 사용자 성과

- 냉각기 후 "안 삼" 선택률 **30%+**
- "이 앱 덕분에 합리적으로 결정했다" 주관 응답 **70%+**

### 제품 성과

- 등록 → 냉각기 완료까지 도달률 **50%+**
- 7일 리텐션 **20%+**

### 학술 성과 (팀플)

- 핵심 루프 시연 작동
- 디자인 의사결정 근거 문서화

### 의도적 Non-goal 메트릭

- ❌ DAU·세션 길이 상승 — 덜 쓰는 것이 성과
- ❌ "안 삼" 횟수 자체 최대화 — informed decision이 목표지 억제 아님
- ❌ 절약 금액 누적 — 크라우딩 아웃

## 9. 안 만드는 것들

### 지금은 안 하지만 나중에 할 것 (Phase 2)

- PWA 홈 배지
- URL 붙이면 상품명/가격 자동 파싱
- OCR, 공유시트, 북마클릿 진입점 확장
- 계정 설정, 탈퇴, 데이터 삭제 플로우
- 추가 로그인 방식
- 친구끼리 공유하는 소셜 기능 (Phase 2 최우선)

### 절대 안 하는 것

- **절약 금액 누적 / 포기 스트릭 / 뱃지** — 숫자 올리기가 목적이 되면 필요한 것도 안 사게 됨
- **예산 잔액 추적** — 잔액 정확히 알면 오히려 "아직 남았네" 하고 더 쓴다는 연구가 있어
- **쇼핑앱 열 때 차단** — one sec이라는 다른 앱 영역
- **벌금형** — 사용자마다 효과 편차가 커
- **게이미피케이션** — 억제가 목적이 아니니까
- **쇼핑중독 치료** — 임상 영역이라 앱이 다루면 위험해
- **상품 이미지 (직접 업로드, OG 추출 등 방법 불문)** — 이미지는 wanting을 되살려서 냉각 효과를 약화시켜. 냉각기 중 정보 숨김 원칙과 정면 충돌. 상세 근거는 `../archive/adr-no-product-image.md`

## 10. 릴리스 계획

### MVP (현재)

7개 화면 + 로그인 기반 영구 저장 + mock AI chat. 배포: https://prototype-sandy-ten.vercel.app

돌아가는 것:
- 7개 화면 전부 구현 (홈, 등록, 냉각중, AI Chat + Decide, 기록, About, 구버전 호환)
- 최소 로그인 방식 1개
- 계정 기반 등록/결정/대화 기록 저장
- AI 대화 + 팩트 요약 + 대칭 결정 버튼의 4단계 Decide 플로우
- 단일 폼 등록 + 봉인 애니메이션
- 냉각기 만료 알림
- 냉각기 만료 시 결정 대기 상태 표시
- 기록 월별 그룹핑 + 대화 transcript 다시 보기

## 11. 리스크

| 리스크 | 영향 | 완화 |
|--------|------|------|
| 로그인 장벽 | 등록 전에 이탈할 수 있음 | 로그인 방식 1개로 최소화 + About에서 앱 목적 설명 |
| 사용자 데이터 분리 오류 | 다른 사용자 기록 노출 또는 저장 실패 | 사용자별 데이터 분리 요구사항을 개발 구현/QA에서 명시적으로 검증 |
| AI 반박 깊이 부족 | 초기 사용 경험이 밋밋할 수 있음 | 현재 대화에서 나온 사실과 구체 질문·산수 중심으로 진행 |
| AI hallucination | 없는 사실을 지어내면 신뢰 파괴 | 현재 등록 정보와 현재 대화 내용 밖의 사실은 사용하지 않도록 프롬프트에 명시 |
| 냉각기 우회 욕구 | 사용자가 저장된 상태를 직접 바꾸려 할 수 있음 | 클라이언트에서 임의 수정 불가한 저장 구조와 상태 전이 검증 필요 |
| "안 삼"이 목적화 | 필요한 것도 안 사게 되는 역효과 | 절약 금액 비노출 + 대칭 버튼 + 중립 라벨로 방지 |
| 쇼핑중독자 오용 | 앱이 치료 도구로 오인됨 | About 페이지에 면책 문구 + 타겟 외 명시적 배제 |
