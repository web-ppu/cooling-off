## 1. 한 줄 요약

쿨링오프는 "원함(wanting)"의 도파민 스파이크와 실제 결제 사이에 시간과 대화를 넣어서, "좋아함(liking)"을 미리 예상해볼 수 있게 만드는 마찰형 자기구속장치(Commitment Device)야.

---

## 2. 타겟 사용자

### Primary — 합리화형 충동구매자 (MZ)

"이거 사면 더 나은 내가 될 거야" 류의 미래 자아 환상에 취약한 사람.

- 생산성 도구, 전자기기, 자기계발 소비에 약함
- "실용적이야" / "3년은 쓸 거야" / "일당 계산하면..." 같은 자기설득 패턴
- 나중에 돌이켜보면 "그때 그거 충동이었네" 인정할 수 있는 사람
- 명품이나 수집 같은 소비는 안 함

### 타겟 아님

| 타입 | 배제 이유 |
|------|----------|
| 과시형 / 멍청소비 | 충동을 문제로 인식 안 함 |
| 수집가 / 덕질 | "실용" 개념 무의미 |
| 생활비 낭비형 | 한 번의 "결정 시점"이 없음 |
| 쇼핑중독 (임상) | 치료 영역. 앱이 다루면 위험함 |

### Positioning vs Usage

포지셔닝은 합리화형으로 좁게 잡되, 실제 가입과 사용은 누구나 가능하게. Crossing the Chasm 원칙.

---

## 3. 왜 이 앱이어야 하나

### "갖고 싶다"와 "좋아한다"는 다른 감정이야

사기 전 흥분이 산 후 만족보다 항상 크거든. 뇌에서 wanting과 liking은 아예 다른 회로야. 시간이 지나면 wanting이 식고, 그때 다시 판단하면 더 정확해.

### 체크리스트 같은 자기 점검은 안 먹혀

자기가 쓴 답을 자기가 검토하는 구조라, "실용적이야"로 스스로를 설득하는 사람한테 뚫려. 체크리스트든 숙고 메시지든 같은 한계가 있어.

### 남의 문제는 잘 보이는데 내 문제는 못 보거든

심리학에서 Solomon의 역설이라고 불러. 자기 문제엔 형편없는데 타인 문제엔 현명한 현상. 외부 관찰자와의 대화가 이 gap을 뚫는 유일한 방법이야.

### 과거 기록은 이 앱만 갖고 있어

앱은 사용자가 전에 뭘 등록하고 어떻게 결정했는지 기록을 갖고 있어. ChatGPT나 친구는 이걸 몰라. 결정 시점에 AI가 이 기록을 꺼내서 반박하는 게 핵심 차별점.

## 4. 원칙

1. **사전 확인** — 산 다음에 취소하게 하는 게 아니라, 사기 전에 한 번 멈추게 해. 이미 내 거가 된 다음엔 취소를 잘 안 하거든.
2. **default = 삭제** — 아무것도 안 하면 자동 삭제. "사겠다"를 적극적으로 선택해야만 구매 결정이 됨.
3. **절약 금액 안 보여줌** — "N원 절약했어!" 같은 숫자 안 보여줘. 그 숫자 올리는 게 목적이 되면 필요한 것도 안 사게 되니까. 스트릭/뱃지도 같은 이유로 없어.
4. **대칭 버튼** — [안 삼]/[삼] 버튼이 똑같은 크기, 똑같은 색. 어느 쪽이 정답이라고 유도 안 해. 과장 칭찬이나 비꼼도 없음.
5. **친구체** — 사용자한테 말 걸 때는 친구처럼 반말. 존댓말, "정말 필요한가요?" 같은 심문체 금지.
6. **30초 등록** — 등록은 30초 안에 끝나야 해. 복잡한 단계 없이 이름, 가격, URL, 왜 사고 싶은지 한 줄이면 됨.
7. **냉각기 중 정보 숨김** — 냉각기 동안은 물건 정보를 일부러 안 보여줘. 다시 보면 "역시 사야 해" 생각이 되살아나니까.
8. **AI = 팩트 반박자** — AI는 "사지 마"라고 말하지 않아. 과거 기록이랑 대조해서 질문만 던지고, 최종 결정은 항상 사용자.

## 5. 사용 흐름 + 냉각기 테이블

### 사용 흐름 (6단계)

```
① 등록 (단일 폼, 30초)
   ↓ 봉인 애니메이션
② 봉인·냉각 (가격별 5-tier 타이머)
   ↓ 냉각기 만료
③ 홈 최상단 픽업 카드 (warm amber)
   ↓ 카드 탭
④ AI Chat (Phase A, 1~3분)
   ↓ AI [END] or 사용자 escape or hard cap
⑤ Decide (Phase B, 대칭 버튼)
   ↓
⑥ 기록 (결정 N개 중립 카운트)
```

### 가격별 냉각기

| 가격 | 기간 |
|------|:---:|
| ≤ 5만원 | 1일 |
| 5~10만원 | 2일 |
| 10~30만원 | 7일 |
| 30~100만원 | 14일 |
| 100만원+ | 30일 |

## 6. 기능 요구사항

### FR-1. 상품 등록 (단일 폼)

단일 페이지 폼, 4 필드. Wizard나 step progress 없음. 30초 이내 완료 목표.

1. **이름** (필수)
2. **가격** (필수, 입력하면 냉각기 기간이 바로 보여)
3. **URL** (선택)
4. **"왜 사고 싶어?"** free text 1~3줄 (선택이지만 강하게 권장)
   - 서브카피: "14일 뒤 돌아왔을 때 네가 읽게 될 말이야"

완료 시 봉인 애니메이션 → 홈 이동. 30초 이내 취소 가능.

### FR-2. 냉각기 (가격별 5-tier)

가격 기반 자동 배정. 등록 직후 30초 grace period로 실수 취소 가능. 이후 삭제 불가 (commitment device 원칙). 냉각기 중에는 상품명, 가격, URL 전부 비노출 — 타이머만 보여줌.

### FR-3. Decide 플로우 (2-phase: AI Chat → Decide)

냉각기가 끝난 아이템의 픽업 카드를 탭하면 시작.

- **Phase A (AI Chat)**: 바로 대화 시작. 보통 3~6턴, 너무 길면 10턴에서 자동 종료 (첫 사용자는 5턴). "결정하러 갈게" 버튼으로 대화 중에 넘어갈 수도 있어.
- **Phase B (Decide)**: 방금 나눈 대화 전체를 펼쳐놓고, 대칭 [안 삼] / [삼] 버튼으로 결정. 결정 후 5초 안에 실행 취소 가능.

### FR-4. 결정 & Undo

[안 삼] / [삼] 탭 → 즉시 기록 + 5초 실행 취소 토스트. 중립 라벨 — "포기"/"구매" 같은 편향된 용어 안 씀.

### FR-5. 홈 (재방문 픽업존)

- 결정 대기 섹션이 최상단 고정 (warm amber)
- 냉각 중 섹션은 하단 (cool tone)
- 하단 고정 FAB "+ 사고 싶은 거 넣기"
- 빈 상태: "사고 싶은 거 있어? 여기에 일단 넣어둬"

### FR-6. 기록 (결정의 궤적)

- "지금까지 내린 결정 N개" 중립 카운트
- 월별로 묶여서 나옴
- 각 카드 누르면 당시 AI랑 나눈 대화를 다시 읽을 수 있어
- 라벨은 "삼" / "안 삼"
- **금지**: 절약 금액 합산, 포기율, 스트릭

### FR-7. Blank Waiting (냉각기 중 접근)

타이머만 보여주고, 상품 정보 전부 비노출. "사지 마세요" 같은 설득 카피도 없음. 그냥 조용히 기다려.

### FR-8. About 페이지

앱 정체성(wanting vs liking, commitment device), 과학 근거 요약, 사용법 요약, 주의 문구(데이터 유실 경고 + 쇼핑 중독 면책).

### FR-9. 돌아옴 메커니즘

현재 MVP는 "다음 충동 시 재방문 픽업 카드(홈 ready-first)"만 구현. PWA 홈 배지, Web Push 알림은 Phase 2.

### FR-10. AI Chat Layer

Decide 단계의 핵심 메커니즘. 정적 체크리스트는 합리화형에 바이패스되니까, full-screen multi-turn chat으로 전환한 거야. 상세 프롬프트 설계는 `../engineering/ai-prompt-v1.md` 참조.

## 7. AI 대화 컨셉

### 시작

항상 같은 질문: "네 말 들어볼게. 왜 이거 지금 사고 싶어?"

### AI가 반박하는 4가지 방법

매 턴마다 AI가 가장 강한 증거가 있는 방법을 골라:

- **추상적 → 구체 숫자 요구**. "매일 쓴다고? 지난 2주 몇 번?"
- **과거 패턴 인용**. 비슷한 거 포기한 기록 있으면 꺼냄. "3개월 전에도 비슷한 거 봤잖아"
- **모순 지적**. 등록할 때 적은 이유랑 지금 말이 다르면 지적
- **산수**. 숫자를 말하면 산수를 해줌. "주 2번이면 월 8번, 89만원 ÷ 8 = 한 번에 11,000원"

### AI가 절대 안 하는 것

- "사지 마" 같은 지시
- "낭비야" 같은 도덕 평가
- "예산부터 세워봐" 같은 일반 조언
- 과도한 공감
- 기록에 없는 사실 지어내기
- 최종 결정 내리기

### 대화 종료

세 가지 경우:

1. 사용자가 "솔직히..." 같은 자각을 보이면 AI가 마무리. 마지막은 항상 "결정은 네가 해. 결정하러 가자."
2. "결정하러 갈게" 버튼을 직접 눌러도 바로 종료
3. 너무 길어지면 자동 종료 (보통 10턴, 첫 사용자는 5턴)

### 첫 사용자 (cold start)

과거 기록이 없으면 AI 반박이 약해. 추상→구체 질문이랑 산수만 가능하고, 과거 패턴 인용은 못 해 (없으니까). 대화도 5턴으로 짧고, 마지막에 "첫 등록이라 기록 못 꺼냈어. 다음부턴 네 패턴으로 더 파고들 수 있어"라고 안내.

## 8. 성공 메트릭

### 사용자 성과

- 냉각기 후 "안 삼" 선택률 **30%+**
- "이 앱 덕분에 합리적으로 결정했다" 주관 응답 **70%+**

### 제품 성과

- 등록 → 냉각기 완료까지 도달률 **50%+**
- 7일 리텐션 **20%+**

### 학술 성과 (팀플)

- 핵심 루프 시연 작동
- 디자인 의사결정 근거 문서화

### 의도적 Non-goal 메트릭

- ❌ DAU·세션 길이 상승 — 덜 쓰는 것이 성과
- ❌ "안 삼" 횟수 자체 최대화 — informed decision이 목표지 억제 아님
- ❌ 절약 금액 누적 — 크라우딩 아웃

## 9. 안 만드는 것들

### 지금은 안 하지만 나중에 할 것 (Phase 2)

- 푸시 알림, PWA 홈 배지
- URL 붙이면 상품명/가격 자동 파싱
- OCR, 공유시트, 북마클릿 진입점 확장
- Supabase 전환 (로그인, 다기기 동기화)
- 친구끼리 공유하는 소셜 기능 (Phase 2 최우선)

### 절대 안 하는 것

- **절약 금액 누적 / 포기 스트릭 / 뱃지** — 숫자 올리기가 목적이 되면 필요한 것도 안 사게 됨
- **예산 잔액 추적** — 잔액 정확히 알면 오히려 "아직 남았네" 하고 더 쓴다는 연구가 있어
- **쇼핑앱 열 때 차단** — one sec이라는 다른 앱 영역
- **벌금형** — 사용자마다 효과 편차가 커
- **게이미피케이션** — 억제가 목적이 아니니까
- **쇼핑중독 치료** — 임상 영역이라 앱이 다루면 위험해

## 10. 릴리스 계획

### MVP (현재)

7개 화면 + mock AI chat + localStorage. 배포: https://prototype-sandy-ten.vercel.app

돌아가는 것:
- 7개 화면 전부 구현 (홈, 등록, 냉각중, AI Chat + Decide, 기록, About, 구버전 호환)
- AI 대화 2단계 플로우, escape 버튼, 자동 종료, 첫 사용자 분기
- 단일 폼 등록 + 봉인 애니메이션
- 냉각기 30초 주기 자동 전이
- 기록 월별 그룹핑 + 대화 transcript 다시 보기
- 시연용 샘플 데이터

### Phase 2

| 영역 | 내용 |
|------|------|
| AI | Claude API 실제 연결 (streaming + prompt caching) |
| 프롬프트 | 5가지 시나리오 반복 개선 |
| PWA | manifest + Service Worker + Web Push + 홈 배지 |
| 데이터 | Supabase 전환 (로그인, 다기기 동기화) |
| 진입점 | 공유시트, 카카오톡, 북마클릿, OCR |
| 자동화 | URL 붙이면 상품명/가격 자동 파싱 |
| 소셜 (최우선) | 재무 버디 초대, 결정 기록 공유, 익명 카운터 |
| 접근성 | 키보드 네비, 화면 읽기, 모션 줄이기 |

### Open Questions

- AI Chat 실제 API 연결 시 응답 품질 검증 방법
- Cold start 분기에서 과거 기록 없이도 충분한 반박 깊이를 만들 수 있는지
- 반복 충동 감지 (같은 URL 3번 이상 등록 시) 처리 방법
